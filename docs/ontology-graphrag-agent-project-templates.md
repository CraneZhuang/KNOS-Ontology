# 本体 + GraphRAG + Agent 项目工作模板

配套阅读：[从 0 到 1 落地手册](ontology-graphrag-agent-delivery-handbook.md)。

本文件可按场景复制使用。客户会前资料与内部技术模板分区，避免让客户填写技术实现细节。空白项用 `____` 填写；未知项明确写“待确认”，不能按“已具备”处理。接口、权限、数据质量和业务规则未验证时，相关范围与工作量标记为“暂时无法评估”。

## 使用约定

| 项目 | 填写规则 |
|---|---|
| 文档信息 | 项目：____；版本：____；日期：____；维护人：____ |
| 编号 | 场景 `SC-__`；需求 `REQ-__`；数据/接口 `DATA-__`；本体 `ONT-__`；规则 `RULE-__`；工具 `TOOL-__`；测试 `TC-__`；证据 `EV-__`；验收 `AC-__`；风险 `RS-__` |
| 事实状态 | 已验证事实 / 业务方陈述待验证 / 设计假设 / 待确认问题 |
| 证据 | 写明链接或受控路径、记录编号、时间、提供方、验证人；涉及敏感数据时使用脱敏副本 |
| 变更 | 记录变更原因、受影响场景及验收项、批准人和生效版本 |
| 数字 | 区分历史基线、试验结果、建议目标与已签核阈值；不能互相替代 |

| 场景 / 用户 | `SC-01`；供应链计划员评估工厂 `S-A` 的停供事件；采购负责人确认应对方案 |
| 痛点与真实事件资料 | 候选痛点：查影响慢、库存口径不一致、替代资格不清。尚未访谈，两个真实事件与现有系统清单待客户提供 |
| 触发 / 输入 | 收到“工厂 S-A 预计停供 7 天”的通知；输入事件记录、工厂标识、发生时间、评估截至时间和目标收货工厂 |
| 事实 / 假设 / 待确认 | 本例没有已验证客户事实；假设 S-A 供应物料 C-1；待确认有效供货关系、库存状态、需求、在途到货和通知真实性 |
| 数据 / 接口 | 候选来源为采购、仓储、生产计划与质量资料，拟登记为 `DATA-01`；接口方式与身份授权均“未提供”，不可宣称可实时查询 |
| 本体范围 | `ONT-01`：供应商工厂、物料版本、收货工厂、供货安排、需求、库存时点和中断事件；供货安排记录有效期及适用地点 |
| 规则 / 计算 | 先按有效供货安排圈定物料；按地点、状态和时间计算可用到货与需求缺口。规则由计划负责人确认，不能由模型自行生成损失金额 |
| 输出 | 受影响候选物料及生产任务、逐日缺口、依据、未知条件和需核查事项；关系路径只能解释依赖，不能单独证明停产 |
| GraphRAG 用例 | `TC-01`：在固定截至时间，以目标工厂计划员身份查询影响；gold 为该身份可见的事件记录、有效供货安排、需求及库存证据；先放入开发集 |
| 必含 / 禁止 | 必含截至时间、条件与数据缺口；禁止将“库存可用 3 天、停供 7 天”直接断言为“停产 4 天”；禁止引用无权访问的其他工厂资料 |
| Agent 工具 | `TOOL-01` 为拟设计的只读查询与计算工具，名称仅作设计标识；首期建议生成评估草稿，实际权限须经接入验证与审批确认 |
| 人工接管 / 动作权限 | 供货关系不明确、库存过期或证据冲突时交计划员核查；本例不包含自动采购或调整生产；如后续需要，另立工具与审批卡 |
| 基线与验收 | 人工耗时、漏查影响与数据正确性基线均待采集；指标分子、分母和阈值待共同签核；验收覆盖正常、缺失、过期、冲突、越权和更新情况 |
| 版本 / 发布 | 设计草案 `SC-01-v0`；数据水位、本体、模型及索引版本在试验时登记；未完成接入和验收，不进入生产发布 |
| 依赖 / 当前结论 | 依赖真实事件、主数据映射、库存与需求口径、只读授权及业务验收人；当前可推进访谈和样本验证，生产接入工期与效果暂时无法评估 |
